# Paquete utilizable, conversión y entrega

## Contrato de piezas

Listar lo encargado antes de construir. Para cada pieza registrar destinatario,
función, fuente editable, derivados, dependencia y estado. Incluir instrumentos,
láminas, lecturas, tarjetas y guías nombradas en la clase; no exigir todos los
formatos a un encargo que solo requiere uno. Un «recurso pendiente» no es un recurso.

| Destinatario | Contenido propio | Lo que se mantiene separado |
|---|---|---|
| Estudiante | Lectura/recurso, consigna, actividad y espacio suficiente para responder. | Claves, notas del profesor, dictámenes e instrucciones de carga. |
| Docente | Planificación, libreto conducible, pauta, ejemplos y qué preparar/imprimir. | Credenciales, historial comercial y reglas internas de otros clientes. |
| Plataforma | Respuestas y adjuntos en el campo correcto, enunciado y límites propios. | Libreto íntegro pegado como respuesta, notas de auditoría y datos inventados. |

## Comprobar dependencias

Abrir cada recurso que el libreto menciona. Verificar texto, título, números,
escala, clave, leyenda, imagen y espacio de respuesta que la actividad necesita.
Un plano cartesiano tiene ejes, graduación, unidades y legibilidad a tamaño real;
un apoyo no anticipa la solución cuando se pretende evaluar la habilidad.

Si cambia el objetivo, una experiencia, un gráfico o una pregunta, revisar todo
lo que depende de ello: pauta, rúbrica, ficha, presentación, guía y avisos. Cambiar
solo la fuente editable deja contradicciones en lo que el docente abre.

Registrar recursos externos con autor, fuente, fecha y condición de uso. Para
imágenes generadas conservar prompt, proveedor, versión y original en expediente
privado; verificar contenido, cantidades, detalles y texto antes de integrar.
Los diagramas de precisión pueden requerir construcción vectorial. La imagen
de acompañamiento no se usa como prueba de hechos ni se presenta como fotografía
documental. El proveedor y sus permisos se toman del entorno vigente, no de una
nota histórica de otro equipo.

## Conversión y edición real

| Riesgo | Comprobación y corrección |
|---|---|
| Texto perdido | Comparar por campo/bloque, no solo concatenando todo el documento. |
| Número convertido en lista | Conservar año y valores; revisar inicio y continuidad de listas en HTML y Word. |
| Aviso cambiado de lugar | Conservar orden de la fuente; el aviso viaja con el bloque al que corresponde. |
| Campo vacío o no interpretado | Distinguir ausencia, vacío y error de lectura; nunca reportar limpio por no encontrarlo. |
| Tope o contador incorrecto | Medir el texto que realmente se copia, no una versión previa o el rótulo. |
| Módulo agregado al consolidado | Verificar si habilita contenido para copiar que antes no se ofrecía; conservar bloqueo y avisos pertinentes. |
| Editable solo en apariencia | Cambiar un campo, pregunta o tamaño y comprobar que se puede editar sin reconstruir una imagen. |
| Presentación que una biblioteca abre | Abrir el archivo en el programa de uso real; la lectura XML no acredita apertura por el docente. |
| Fuente nueva, PDF antiguo | Regenerar solo los derivados afectados y volver a abrirlos. |

Usar el editor o conversor que preserve el formato del encargo. En instalaciones
Portabot se respeta su restricción vigente de no usar LibreOffice; en otro entorno
no se inventa una restricción universal, pero la apertura y comparación siguen
siendo necesarias. Una reconversión no autoriza a regenerar el contenido aprobado.

## Preimpresión

Revisar A4, márgenes, tamaño real, líneas, pie y saltos de página con el PDF
renderizado. Las líneas se miden en unidades de impresión, no se declaran por una
clase CSS. Reservar espacio acorde a la respuesta esperada. No bajar letra ni
comprimir escritura para cumplir una cantidad fija de páginas.

Comprobar sin fondos de impresión y en escala de grises cuando se use tinta
negra. La clave, un color o un glosario no debe desaparecer. Conservar identificación
breve en hojas que pueden separarse. Abrir todas las páginas y revisar tablas,
imágenes, numeración y pie; no usar solo la primera página como evidencia.

Una revisión digital permite declarar PDF revisado. Una impresión real y una
lectura con el equipo OMR son pruebas adicionales que no se simulan con un dibujo.

## Publicar solo dentro del alcance

La identidad del destino se acredita por el sistema propietario. Antes de una
escritura externa: lectura actual, simulación sin efectos, respaldo recuperable,
aplicación exacta y relectura independiente. Un hash sin los bytes no restaura
un documento; un campo llamado dry-run no demuestra que no haya efectos.

No sobrescribir una edición del docente. Descargar la versión actual, integrar
su contenido y justificar el cambio. Verificar la cadena de carpetas del destino;
el nombre parecido no acredita pertenencia. No limpiar archivos de otros módulos
ni de editor desconocido para ordenar la entrega.

La existencia local, publicación, nombre, contenido correcto y aviso son estados
independientes. Comprobar la versión remota que abrirá el destinatario. Un enlace
se prueba antes de enviarlo. Si falta permiso de comunicación, conservar el
borrador y el estado «verificado, aviso pendiente», sin inventar envío o recepción.

## Cierre útil

Dejar archivo o enlace directo y explicar qué debe leer, editar, adjuntar,
imprimir o preparar el docente. Informar cambios y límites con lenguaje simple.
No trasladar pendientes del equipo como tareas de redacción que se prometió hacer.
Un reclamo de claridad se resuelve mirando la consigna y el uso, no defendiendo
el material con generalidades. Registrar el cierre en el repositorio propietario.
